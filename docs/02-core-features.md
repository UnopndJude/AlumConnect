# AlumConnect 기본 기능 기획

## 개요

인천과학고등학교 동문 커뮤니티의 핵심 기능 정의

---

## 1. 회원 시스템

### 1.1 회원가입

#### 필수 정보

| 항목     | 설명             | 검증                 |
| -------- | ---------------- | -------------------- |
| 이메일   | 로그인 ID로 사용 | 형식 검증, 중복 체크 |
| 비밀번호 | 최소 8자         | 영문+숫자 조합       |
| 이름     | 실명             | 2-20자               |
| 졸업기수 | 1기 ~ 현재       | 숫자 범위 검증       |

#### 선택 정보 (가입 후 설정 가능)

- 닉네임 (커뮤니티 표시용)
- 프로필 사진

#### 가입 플로우

```
[기본 정보 입력] → [동문 DB 매칭] → [퀴즈 인증] → [이메일 인증] → [가입 완료]
                        ↓                ↓
                  [매칭 실패]      [퀴즈 실패]
                        ↓                ↓
                  [관리자 검토 요청] ←───┘
```

#### 동문 인증 방식: 퀴즈 기반 인증

**2단계 인증 시스템**

1. **1단계: 동문 DB 매칭**
2. **2단계: 학교 퀴즈 통과**

---

### 1.1.1 동문 DB 매칭 (1단계)

#### 매칭 정보

| 입력 항목 | DB 대조          |
| --------- | ---------------- |
| 이름      | 졸업생 명단      |
| 졸업기수  | 해당 기수 명단   |
| 생년월일  | (선택) 추가 검증 |

#### 매칭 결과

- **완전 매칭**: 이름 + 기수 일치 → 퀴즈 단계로
- **부분 매칭**: 이름만 일치 → 추가 질문 후 퀴즈
- **매칭 실패**: 명단에 없음 → 관리자 검토 요청

#### 동문 DB 구조

```typescript
interface AlumniRecord {
  name: string // 이름
  graduationClass: number // 졸업기수
  birthYear?: number // 출생연도 (선택)
  isRegistered: boolean // 가입 여부 (중복 방지)
}
```

### 1.1.2 학교 퀴즈 인증 (2단계)

#### 퀴즈 구성

- **총 문항**: 5문제 (풀에서 랜덤 선택)
- **통과 기준**: 4문제 이상 정답
- **재시도**: 3회 (24시간 후 초기화)
- **제한 시간**: 문항당 30초

#### 퀴즈 유형

**Type A: 학교 기본 정보**

```
Q: 인천과학고등학교의 개교 연도는?
   ① 1992년  ② 1994년  ③ 1996년  ④ 1998년

Q: 학교 소재지는?
   ① 연수구  ② 남동구  ③ 미추홀구  ④ 부평구
```

**Type B: 학교 시설/공간**

```
Q: 기숙사 이름은?
   ① 과학관  ② 청운관  ③ 비룡관  ④ 인송관

Q: 학교 뒷산 이름은?
   ① 문학산  ② 청량산  ③ 계양산  ④ 만월산
```

**Type C: 학교 문화/전통**

```
Q: 교훈은?
   ① 창의, 성실, 봉사  ② 진리, 창조, 봉사
   ③ 창조, 탐구, 봉사  ④ 진리, 성실, 창조

Q: 체육대회 전통 경기는?
   ① 축구  ② 피구  ③ 줄다리기  ④ 계주
```

**Type D: 기수별 맞춤 문제** (선택)

```
Q: [23기] 입학 당시 교장선생님 성함은?
Q: [15기] 당시 남자 기숙사 호실 구조는?
```

#### 퀴즈 문제 DB 구조

```typescript
interface QuizQuestion {
  id: string
  type: "basic" | "facility" | "culture" | "class_specific"
  question: string
  options: string[] // 4지선다
  correctIndex: number // 정답 인덱스
  applicableClasses?: {
    // 기수별 문제인 경우
    from: number
    to: number
  }
  difficulty: "easy" | "medium" | "hard"
}
```

#### 퀴즈 결과 처리

| 결과         | 처리                           |
| ------------ | ------------------------------ |
| 4-5문제 정답 | 통과 → 이메일 인증 단계        |
| 3문제 정답   | 1회 재시도 기회                |
| 0-2문제 정답 | 실패 → 재시도 또는 관리자 검토 |

#### 문제 품질 관리

**자동 품질 체크**

- 중복 문제 감지 (유사도 검사)
- 금칙어 필터링
- 최소 글자 수 검증

**출제 후 모니터링**

```typescript
interface QuestionStats {
  timesAsked: number // 출제 횟수
  correctRate: number // 정답률
  skipRate: number // 건너뛰기 비율
  reportCount: number // 신고 횟수
}
```

**자동 조치**
| 조건 | 조치 |
|------|------|
| 정답률 95% 이상 | 난이도 "쉬움" 태그, 출제 빈도 ↓ |
| 정답률 30% 이하 | 난이도 "어려움" 태그, 검토 요청 |
| 신고 3회 이상 | 자동 비활성화 → 관리자 검토 |
| 건너뛰기 50% 이상 | 문제 품질 검토 요청 |

---

#### 출제자 인센티브

**뱃지 시스템**
| 뱃지 | 조건 |
|------|------|
| 🌱 첫 출제 | 첫 문제 채택 |
| ✍️ 출제자 | 10개 이상 채택 |
| 🏆 베스트 출제자 | 50개 이상 채택 |
| ⭐ 명예의 전당 | 채택률 90% 이상 (20개+) |

**활동 포인트** (향후 확장)

- 문제 출제: +5점
- 문제 채택: +10점
- 검증 참여: +2점

#### 퀴즈 문제 DB 구조 (확장)

```typescript
interface QuizQuestion {
  id: string

  // 문제 내용
  type: "basic" | "facility" | "culture" | "class_specific"
  question: string
  options: string[]
  correctIndex: number
  explanation?: string // 출제 근거

  // 대상 기수
  applicableClasses?: {
    from: number
    to: number
  }

  // 출제 정보
  authorId: string // 출제자 ID
  authorClass: number // 출제자 기수
  createdAt: Date

  // 검증 상태
  status: "pending" | "approved" | "rejected" | "disabled"
  approvedAt?: Date
  votes: {
    odId: string
    vote: "approve" | "reject" | "skip"
    reason?: string
    votedAt: Date
  }[]

  // 통계
  stats: {
    timesAsked: number
    correctCount: number
    skipCount: number
    reportCount: number
  }

  // 난이도 (자동 계산)
  difficulty: "easy" | "medium" | "hard"
}
```

#### 관리자 기능 (최소화)

관리자는 커뮤니티가 해결 못하는 경우만 개입

- 신고된 문제 최종 판단
- 보류된 문제 처리
- 시스템 설정 (채택 기준, 기한 등)
- 문제 풀 전체 통계 조회

### 1.2 로그인/로그아웃

#### 로그인 방식

- 이메일 + 비밀번호
- (향후) 소셜 로그인 검토 (Google, Kakao)

#### 세션 관리

- 로그인 유지: 7일 (설정 가능)
- 자동 로그아웃: 30일 미접속 시

### 1.3 비밀번호 관리

#### 비밀번호 찾기

```
[이메일 입력] → [인증 링크 발송] → [새 비밀번호 설정]
```

- 인증 링크 유효시간: 24시간
- 최근 3개 비밀번호 재사용 불가

#### 비밀번호 변경

- 현재 비밀번호 확인 필요
- 변경 시 다른 기기 세션 종료 옵션

### 1.4 회원 탈퇴

#### 탈퇴 절차

```
[탈퇴 요청] → [비밀번호 확인] → [탈퇴 사유 선택] → [7일 유예] → [완전 삭제]
```

#### 데이터 처리

- 작성 게시글: 작성자 "탈퇴한 회원"으로 표시
- 댓글: 동일 처리
- 개인정보: 완전 삭제

## 2. 프로필 관리

### 2.1 기본 프로필

#### 공개 정보 (필수)

| 항목      | 설명                    |
| --------- | ----------------------- |
| 표시 이름 | 닉네임 또는 실명 (선택) |
| 졸업기수  | 00기 형식               |
| 가입일    | 자동 기록               |

#### 선택 공개 정보

| 항목      | 공개 범위 설정         |
| --------- | ---------------------- |
| 현재 상태 | 전체 / 동문만 / 비공개 |
| 소속      | 전체 / 동문만 / 비공개 |
| 분야      | 전체 / 동문만 / 비공개 |
| 지역      | 전체 / 동문만 / 비공개 |
| 연락처    | 비공개 / 요청 시 공개  |

### 2.2 프라이버시 설정

#### 프로필 공개 수준

- **공개**: 모든 동문에게 노출
- **반공개**: 검색 불가, 직접 링크로만 접근
- **비공개**: 관리자만 열람 가능

#### 연락 설정

- 쪽지 수신: 허용 / 동기만 / 거부
- 이메일 알림: 허용 / 거부

1. 동문 DB 스키마 및 데이터 구축
2. 초기 퀴즈 문제 시드 데이터 (관리자가 20~30문제 등록)
3. 회원가입 플로우 재구현
   - 기본 정보 입력 UI
   - 동문 DB 매칭 API
   - 퀴즈 진행 UI
   - 퀴즈 채점 API
4. 비밀번호 해싱 적용
5. 이메일 인증 추가

### Phase 2: 동문 참여형 퀴즈 시스템

1. 퀴즈 출제 UI (/quiz/new)
2. 퀴즈 검증 시스템 (/quiz/verify)
3. 내 출제 현황 (/quiz/my)
4. 출제자 뱃지 시스템

### Phase 3: 관리 도구

1. 수동 검토 요청 처리
2. 신고 문제 처리
3. 퀴즈 통계 대시보드

### Phase 3: 프로필 강화

1. 프라이버시 설정 UI
2. 공개 범위 설정
3. 프로필 수정 기능

### Phase 4: 고도화

1. 기수별 맞춤 문제 시스템
2. 난이도 자동 조정
3. 비밀번호 찾기 기능
